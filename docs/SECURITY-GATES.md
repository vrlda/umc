## Release rule

The project remains experimental while any critical gate is open. In
particular, this document does not authorize production-security claims,
stable promotion of experimental carriers/plugins, or claims of global
passive-anonymity resistance. A release owner must attach dated evidence for
each gate and record unresolved exceptions before signing a release manifest.

## Evidence update procedure

When a gate changes, update this file together with the relevant phase status,
compatibility row, and threat-assessment entry. Link to a test, review record,
CI artifact, or drill report rather than recording a bare pass count. Keep
external account settings out of source control; do not invent credentials
or private keys in repository files.
