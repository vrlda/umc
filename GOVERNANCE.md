# Governance

OpenMesh is maintainer-led and community-informed.

Maintainers are conservative about protocol changes, operator-risk tradeoffs,
and security decisions.

## Roles

### Maintainers

Maintainers are responsible for:

- reviewing and merging changes
- setting release direction
- making security and disclosure decisions
- moderating community spaces
- keeping the project aligned with its mission and principles

### Contributors

Contributors can:

- improve code, docs, tests, and tooling
- propose design changes
- review pull requests and issues
- help with community support and triage

## Decision making

- Small changes should be made through pull requests.
- Larger changes should begin with a public discussion.
- Security, privacy, censorship-resistance, and operator-safety decisions may
  require explicit maintainer approval even when there is broad support.
- When possible, we prefer rough consensus and clear written rationale.
- When consensus is unclear, maintainers decide and document the reasoning.

## Protocol and architecture changes

Changes that affect the protocol, threat model, deployment assumptions, or node
incentives should begin with a public discussion and include clear written
rationale in the pull request or design note.

## Conflict resolution

If a contribution is declined, that does not mean future work on the idea is
unwelcome. Maintainers should explain the main reason for a rejection or pause:

- wrong timing
- unclear scope
- security or privacy concerns
- operator-risk concerns
- maintenance cost

## Donations and influence

Donations help the project continue, but they do not buy roadmap control,
special access, governance power, or merge rights.
